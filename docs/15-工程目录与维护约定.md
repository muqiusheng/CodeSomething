# 工程目录与维护约定

日期：2026年11月12日。适用于当前`new-system/`工程。此次整理按职责确定位置，保留构建根目录、API、课程版本、数据库与端口。

新增文件、组件版本、Git 分支与发布见[命名、版本与 GitHub 发布约定](35-命名版本与GitHub发布约定.md)。

## 仓库文件与本机文件

源码、模块构建文件、依赖锁、课程包、规范和验收摘要进入 Git。课程包、课程锁及其校验输入按原字节保存，避免 Git 自动转换换行导致 SHA-256 变化。

运行数据库、依赖缓存、构建输出、个人导入资料、参考截图、原始验收附件及本机技能副本由 `.gitignore` 排除。验收目录包含阶段 README，以及 R3.4 和 R7 门禁读取的 36 份正反例报告。验收摘要中标记的原始附件路径用于维护者回查。

现有 `release-check` 和 `r7-release-check` 属于阶段发布门禁。2026年11月20日核对发现，当前后端的部分检查器文件已变更，与历史发布锁不一致。当前门禁结果为失败。更新门禁需要根据课程发布契约核对变更并重新生成对应证据。

## 组织依据

- [Maven标准目录布局](https://maven.apache.org/guides/introduction/introduction-to-the-standard-directory-layout)：后端保留`src/main/java`、`src/main/resources`、`src/test/java`和`src/test/resources`，生成文件在`target/`。
- [Vite入门说明](https://vite.dev/guide/)：`index.html`为前端入口，Vite从项目根运行。保留`frontend/index.html`、`vite.config.ts`和独立`package.json`。
- [GitHub忽略文件说明](https://docs.github.com/en/get-started/git-basics/ignoring-files)：根目录声明本地缓存、运行状态和构建产物的忽略规则。

以上资料定义工具约定；前端功能分组、工程工具分组与文档导航是结合本项目作出的工程选择。

## 目录归属

根目录保留项目入口、产品与设计基线、工作约定及配置。`docs/`集中需求、架构、设计、阶段契约、决策和实施追踪；编号文档保留原路径。`scripts/project.ps1`是仓库级常用命令入口，通过自身位置定位工程。

以下路径相对于`new-system/`：

- `frontend/src/main.tsx`：React启动、当前应用壳与路由入口。
- `frontend/src/features/`：home、projects、reviews、profile、settings、tutor、learning。功能专属组件靠近所属功能。
- `features/learning/`：http、sql、boot课程；shared放提交、理解验证与检查报告等通用学习组件。
- `frontend/src/components/`：layout、shared、ui、leibox。共享组件、第三方来源与许可证一起保留。
- `frontend/src/api/`：平台与学习API请求、传输类型和已有客户端缓存。
- `frontend/src/hooks/`、`src/theme/`：共享hooks；主题偏好与浏览器同步。
- `frontend/src/styles/`：原有CSS按原顺序导入，主题色与许可证同目录。
- `frontend/tests/unit/`、`tests/browser/`：单元行为测试；需要真实服务和独立会话的浏览器验收。
- `idea-plugin/`：独立Kotlin/Gradle插件，src/main为实现和描述，src/test为单元/协议/沙箱测试；本地构建输出在build，工具缓存和沙箱在runtime。
- `backend/src/`：Maven布局，沿用api、boot、courses、learning、profile、sql、storage、tutor、workspaces业务包。
- `course-packs/`、`curriculum/`：版本化课程；依赖规划与发布输入锁。已发布内容及路径保持稳定。
- `runner/`：隔离环境与说明。
- `tooling/`：环境、开发、打包、练习工程及发布运行工具。checks放阶段校验，tests放工具行为测试。
- `docs/acceptance/`：阶段验收摘要和门禁样本，各阶段记录当时的命令与结果。
- `runtime/`：本机SQLite、备份、日志、Maven缓存、构建副本和练习工程，不入版本库。

## 维护规则

新增业务组件先选择所属功能；多个功能复用的组件再进入共享目录。保留相对导入，移动后同步调用者。`WorkspaceExtras.tsx`目前仍组合作品预览、能力说明与动效设置，放在`components/shared/`；以后修改相应功能时再拆分，本轮保留运行逻辑。

日常工具留在`tooling/`一级，阶段检查放`checks/`，测试放`tests/`。旧阶段校验仍从仓库根运行，保留原有独立端口、数据及依赖前提。浏览器脚本可能写验收文件或操作课程环境，不作为批跑单元测试。

VS Code工作区隐藏运行数据、依赖与构建目录，普通搜索排除历史证据和参考素材，可在编辑器设置中临时显示。现有数据库、课程和运行中的发布JAR路径保持稳定。本轮只把根目录两个零字节异常文件归档到`runtime/archive/stray-files/`，把一份早期日志归入`runtime/logs/`。

## 迁移与回查

本轮72个文件的新旧路径、前后SHA-256与原文件备份保存在`new-system/runtime/structure-refactor-20261112/`。`moves.json`是清单，`before/`包含修改前的前端源码、测试、工具和当前文档。该备份不入库。新增的工程入口与配置另见本轮验收记录。

回退时先停止涉及前端文件的开发进程，对照清单恢复原路径及调用者；不覆盖后续新增业务修改。历史验收文档不批量改写，避免把旧命令写成新路径下已执行的结果。
