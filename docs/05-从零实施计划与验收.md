# 从零实施计划与验收

2026年11月16日新增全项目验收要求：验证最小工程起步、逐章代码增量、下一章承接、回看不回滚、刷新恢复、旧报告时效及完整项目产物。步骤点击或选择题通过不能代替实际项目代码与运行证据。详见[同一工程项目教学原则](25-同一工程从零完成的项目教学原则.md)。

2026年11月10日建立。阶段编号R0—R8，与旧项目阶段编号完全独立。按交付能力排期，工期在R1环境与接入验证后估算。每个阶段内部按任务ID逐项完成，阶段通过后推进。

## R0 产品与设计基线（本次）

R0.1 整理用户事实、目标、范围和学习流程。R0.2 形成新页面与架构。R0.3 重建六技能及全局工作流。R0.4 保存参考、阶段计划与新对话入口。

产物：PRODUCT、DESIGN、docs/01—06、参考图库、技能来源清单、追踪表。验收：文档链接有效，旧版与新方案有明确边界，安装清单与实际技能匹配。此阶段不包含新应用代码或页面运行验收。

## R1 全新工程与关键可行性

依赖R0。

- R1.1 检查JDK、Node、IDEA、容器、端口与磁盘；为新工程确定独立端口和数据路径。
- R1.2 查官方资料核实当前账号可用的GPT接入路线，最小调用验证授权、响应、停止、限额和重连；记录支持范围与结果。
- R1.3 新建frontend/backend/course-packs/runner结构，锁依赖、建立构建和配置示例；平台数据不进版本库。
- R1.4 建数据库迁移、统一错误、健康接口、应用壳、真实路由和持久化偏好。
- R1.5 完成续学页与工作台基础布局，对照参考并验证多尺寸。

验收：全新工程独立启动；刷新深链接有效；新存储重启可恢复；构建通过；浏览器应用壳可操作。GPT路线给出“真实可用”或有依据的“受阻”结论。受阻时课程与检查继续推进，AI关联任务保持待验收，后续不得宣称全产品AI已完成。

## R2 第一个真实学习闭环（最小可用版）

依赖R1工程及可用隔离执行器，AI接入可独立推进。

- R2.1 编写HTTP/JSON模块首个正式单元：请求、响应、状态码、JSON，含教学、交互示例与理解题。
- R2.2 实现目录配对、文件范围预览、快照提交和幂等检查作业。
- R2.3 建隔离运行与测试结果页，覆盖编译/业务/环境失败、超时和取消。
- R2.4 实现双结果通过规则、预览、下一关与断点续学。任务与规则见[细化计划](08-R2.4双结果完成与续学计划.md)，实际结果见[验收记录](../new-system/docs/acceptance/R2.4/README.md)。
- R2.5 接入分级提示、上下文选择与错误状态；AI未可用时如实显示并保留其他功能。已完成，契约见[网页辅导计划](09-R2.5网页辅导计划与契约.md)，证据见[R2.5验收](../new-system/docs/acceptance/R2.5/README.md)。

验收场景：学员从网页读课，在IDE写一个JSON响应接口，第一次写错→获得准确报告→修复→功能通过→迁移题通过→解锁下一关；服务重启后记录仍在。重复提交不重复完成，环境故障不降低能力，修改代码后旧报告不冒充新结果。AI另有真实上下文响应与停止证据，未接入部分单列。

- R3.3 编写并验证个人任务管理项目：启动、参数、建模、数据访问、CRUD、校验、分页、错误与测试。
- R3.4 逐关减少骨架，建立固定课程包版本与参考实现检查。2026年11月12日工程门禁完成，见[固定版本与发布门禁](14-R3.4课程版本与发布门禁.md)和[R3.4验收](../new-system/docs/acceptance/R3.4/README.md)；真实学习者独立完成与开放讲解按学习回访验证。

## 阶段收尾约定

实现与相关检查通过后更新追踪。发现新问题只补测受影响行为。核心状态用行为测试；样式按浏览器证据验收。报告必须列出未通过项及实际影响；不能因总阶段大部分完成就把未接通的AI或未执行的判题标为完成。
