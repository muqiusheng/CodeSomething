# 系统架构与数据模型

2026年11月16日更新：学习工程按项目持续保存，各章共享当前源码；关卡提交与报告继续绑定不可变快照。完成记录允许没有选择题记录，概念巩固单独关联；项目切换隔离，跨章并发修订冲突拒绝覆盖。适配与验收见[同一工程项目教学原则](25-同一工程从零完成的项目教学原则.md)。

技术选型已在R1首轮落地：React19.2/TypeScript5.9.3/Vite7.2.2，Java21、Spring Boot4.1.2、SQLite JDBC3.54.1.0与Flyway版本化迁移。实际构建和接入范围见new-system/docs/acceptance/R1/。

## 1. 总体结构

本地单用户优先。建议React + TypeScript + Vite前端，Java 21 + Spring Boot后端，分别放`new-system/frontend`与`backend`。开发时代理API，发布时同源提供静态页与API。独立于旧服务端口与存储。

采用模块化单体：学习进度、课程、检查编排、辅导适配、画像复习、项目研究生成、作品。前端只访问平台API；后端连接数据库、版本化课程包、运行器、AI适配器和IDE桥接。研究、生成、检查通过异步作业执行。

`course-packs/`保存发布内容与样例，`runtime/artifacts/`保存快照/日志，`runtime/data/`保存本地学习记录。运行目录不进版本库。默认绑定127.0.0.1，朋友共享另做部署设计。

## 2. 存储与实体

平台已采用SQLite，R1通过Java驱动、迁移、事务与服务重启恢复验证。课程中的MySQL是学习环境，与平台存储分开。实体有稳定ID、时间戳；结果与证据事务写入；后台作业有幂等键与重试状态。R2.2新增预览/配对、目录绑定、Submission与CheckJob存储；Submission原始字节以SQLite BLOB和元数据同事务保存，当前无需外部快照文件双写。R2.3新增V6报告持久化、串行隔离队列、逐项HTTP检查和取消接口；CheckJob已能产生绑定快照的功能报告，关卡完成与能力证据待R2.4。以下其他实体按后续阶段建设。

| 实体 | 关键数据与约束 |
| --- | --- |
| LearnerProfile | 背景、目标、时间、兴趣、自报修订版本 |
| KnowledgeNode | 能力标签、先修边；依赖无循环 |
| CoursePackage / CourseVersion | 目标、先修、来源、状态、内容摘要；发布版本不可原地覆盖 |
| StageDefinition | 版本、教学、任务、检查策略、理解题、完成规则 |

## 3. 接口草案

新前缀`/api/v1`，实现阶段补齐OpenAPI与错误样例。

- `GET /learning/continue`：续学位置与下一动作。
- `GET /courses/{id}/versions/{version}/stages/{stageId}`：指定版本课程。
- `PUT /learning/sessions/{id}`：带版本字段保存步骤，防止旧请求覆盖。
- `POST /submissions`：生成绑定项目快照。
- `POST /check-jobs`：幂等启动检查；`GET /jobs/{id}`查询，`POST /jobs/{id}/cancel`取消。
- `POST /understanding-attempts`：规则判定；完成服务核对双结果。
- R2.4实际契约：`GET /understanding-rules/{course}/{version}/{stage}`读取无答案键的正式情境题；`POST /understanding-attempts`提交jobId、ruleVersion、answers与idempotencyKey，沿用功能作业的Bearer配对令牌。服务端从作业推导课程/关卡/提交，不接受客户端自报通过。`GET /understanding-attempts/jobs/{jobId}`授权读取尝试历史。
- `GET /learning/progress/{course}/{version}`读取关卡完成证据；完成记录在当前本地单用户范围内按课程/版本/关卡唯一，关联提交、功能作业、理解尝试、代码摘要和规则版本。V7追加尝试与完成表，V8保留原位置数据并允许understanding步骤。`GET /learning/continue`返回session、nextAction、checksAvailable、nextStageId和真实进度；保存位置时后续预览返回PREVIEW_ONLY，过时revision返回VERSION_CONFLICT。
- `GET /profiles/me/evidence`与`PATCH /profiles/me/preferences`：查看依据与修订背景。
- `POST /path-proposals/{id}/accept`或`reject`：处理重大调整。
- `POST /tutor/messages`：发送受控上下文；`GET /events?after=...`订阅事件。
- R2.5实际使用`POST /tutor/requests`创建单题辅导，`GET /tutor/requests/{id}`读取状态，`GET /tutor/requests/{id}/events?after=revision`订阅SSE状态快照，`POST /tutor/requests/{id}/stop`停止。已选代码/报告沿用配对Bearer授权。V9的tutor_requests保存问题、帮助等级、上下文清单、快照引用、幂等摘要、回答和状态；不自动重跑中断问题。连接探测由`GET/POST /tutor/connection`提供。详细契约见[docs/09](09-R2.5网页辅导计划与契约.md)。
- `POST /project-requests`：提出题材；`POST /course-versions/{id}/publish`执行发布门禁。

错误包含`code/message/details/retryable/requestId`。后端为状态权威；前端不提前显示已通过。SSE事件包含ID、作业ID、类型与时间；重连先查询状态，再按游标恢复。游标过期时返回快照。取消经后端确认后生效。

## 4. 执行器

R3.2新增SQL独立执行分支，见[SQL契约](11-R3.2SQL教学闭环与运行契约.md)。V10保存sql_attempts、sql_understanding、sql_completions及sql_reset_tokens，SQL完成关联本身的文本快照与报告；不改变原Java完成表外键。CourseController识别固定发布的sql-foundations/1.0.0；LearningProgress与LearningSession分派到当前课程，保留revision/预览/先修规则。Java工作区与作业明确拒绝SQL课程，防止版本号相同而进入HTTP默认策略。

MySQL容器固定摘要、无网络且不挂载平台数据，单次检查使用专库和专用账号；试运行使用独立持久练习库。报告包含SQL/种子/镜像/规则摘要，取消及超时释放连接，平台中断恢复为环境错误。Java多文件/Maven/JDBC网络隔离在R3.3扩展。

学习代码与生成参考实现放独立受限容器或等价隔离环境运行，不在平台JVM直接加载。限制CPU、内存、时长、进程数和日志；固定镜像与受控依赖缓存，默认禁外网，只挂载本次快照与输出目录。

报告绑定环境、测试与代码摘要。超时和取消释放进程/临时文件。无隔离环境时可先交阅读与演示，但真实判题标为待启用，R2不算闭环通过。

## 5. GPT接入可行性门

用户希望使用现有GPT账号额度。R1核实官方支持的账户授权或本地工具路线，检查当前教师账号资格，完成最小真实调用、取消、重连与额度错误验证。网页能登录不能替代调用验证。

`TutorProvider`抽象能力查询、授权状态、回答、取消及错误归类。授权由官方支持流程完成，课程聊天不收cookie或令牌。若现有额度路线不可用，记录明确结论与可选官方路线；付费API由用户另行选择。课程和确定性检查独立开发。

## 6. IDEA与本地桥接

先用最小目录绑定/提交闭环，再开发Kotlin IDEA插件。插件显示任务、允许文件、提交和错误定位；服务端仍负责判定与画像。IDEA版本在R1探测，R4按实际版本验证。

本地桥接以短期配对码换限定会话令牌，校验来源、目录和请求范围，避免其他网页调用本机执行。插件断开后网页仍能查看历史。

## 7. 画像与生成

追加事件 → 归一化证据 → 可解释规则 → 画像快照 → 推荐。早期不使用未经校准的精密掌握百分比。开放解释的AI结论附规则与证据，关键解锁有复核入口。

研究 → 能力映射 → 方案 → 参考实现与测试 → 隔离构建 → 教学检查 → 发布。门禁要求依赖无循环、目标可测、参考通过、来源可追溯。发布后不静默替换正在学习版本。

## 8. 备份边界

备份包含一致性数据库快照、课程版本与作品引用；恢复先验证格式与版本并预览。新系统不自动导入旧数据，不覆盖`code-something/`的源码、data或运行记录。
