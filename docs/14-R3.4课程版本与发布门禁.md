# R3.4课程版本与发布门禁

2026年11月12日。接续[R3.3契约](12-R3.3SpringBoot工程与接续契约.md)，本轮建立已发布课程的固定文件清单和可重复执行的参考检查门禁。课程内容、版本、平台接口和学习数据沿用现有发布。

## 固定版本与骨架

[r34-release-lock.json](../new-system/curriculum/r34-release-lock.json)记录149项输入的SHA-256：HTTP历史版本、SQL、Boot和项目A课程文件，以及Boot运行器源码、资源、镜像锁、MySQL环境和正反例测试定义。门禁拒绝缺失、改写及清单根目录内新增文件。修订课程应建立新版本，保留旧包和历史证据；不能通过刷新本锁覆盖同版本变动。本锁是当前发布基线，新增版本需独立审阅清单、注册映射和相应运行证据。

项目A骨架按完整分层、DTO与签名、接口约定、错误结构、需求与数据、最小工程递进。四个中间关保留需要学员实现的方法体；门禁核对对应TODO数量。最后a-transfer仅有固定pom.xml与Application.java，参考目录单独保留JUnit测试和RUN.md。骨架递减描述表示提供帮助的范围，真实独立程度由后续学习证据评价。

历史生成脚本build-r33-courses.py在读取模板和写入任何文件前检查发布状态；发现已发布1.0.0立即退出。该脚本作为初次创作记录保留，后续版本需使用新目录的创作流程。

## 执行与报告核对

[check-r34-release.mjs](../new-system/tooling/checks/check-r34-release.mjs)核对Boot四章与项目A六关的顺序、版本、教学字段、两道正式题和答案范围、骨架范围与镜像/POM绑定。HTTP和SQL本轮只复核固定文件；其执行证据沿用各自既有验收，不计入本轮十关运行数。

每关要求两份真实隔离运行报告：参考为passed且所有断言通过；行为错误变式为business_error且有失败断言。编译、环境、超时和取消不能充当有效反例。两份报告须绑定同一关卡、课程版本、策略、镜像与已锁定harnessDigest；参考摘要按Java快照协议重新计算并精确匹配，反例摘要必须与参考不同。检查器实现变化需要重新审阅并生成对应运行证据。

以下入口每次创建独立运行目录，清除章节过滤，要求整个JUnit矩阵成功退出后再检查报告，避免拿上次遗留的部分报告补齐本次运行：

```powershell
& ./new-system/tooling/run-r34-release.ps1
```

分步复核已有证据：

```powershell
node --test new-system/tooling/tests/check-r34-release.test.mjs
node new-system/tooling/checks/check-r34-release.mjs --record
node new-system/tooling/checks/check-r31-plan.mjs
```

门禁是本地发布前命令，失败以非零状态退出，不自动修改课程注册、打包部署或写入学习记录。它验证教学材料和确定性功能检查的一致性；用户开放讲解、复制帮助的使用与真实独立完成情况仍属于后续学习验收。现有服务端双结果与先修规则继续生效。

本轮实际命令、运行矩阵与边界见[R3.4验收](../new-system/docs/acceptance/R3.4/README.md)。下一阶段为R4 IDEA插件，先探测实际IDEA版本与插件兼容环境。
