# R6.1公开项目研究与来源契约

本步建立可离线复核的公开项目来源清单，供R6.2能力匹配与方案选择读取。研究归档位于[new-system/research](../new-system/research/README.md)，以[catalog.json](../new-system/research/catalog.json)为结构化入口。当前应用、已发布课程及学习数据库保持原有版本。

## 研究范围与选取

2026年11月12日检索Java/Spring公开样例，优先原作者仓库、可读许可和明确业务范围。首轮选取Petclinic服务端页面版、Petclinic REST后端及JDBC客户数据小练习，覆盖业务实体、服务层与事务、分页和参数化数据访问。Petclinic两个分支归入同一来源家族；三项样例集中在Spring生态。

每项记录仓库原地址、固定40位提交、上游提交时间、实际获取时间、根许可及其证据、依赖声明、所读文件、未观察范围和能力标签。能力映射引用已发布课程ID、版本与关卡ID，并连接到固定源码证据及文字锚点。标签是教学适配判断，学习者的掌握状态仍取自R5真实证据。

## 证据与许可

GitHub REST用于读取仓库、提交和文件树；原始文件按提交SHA读取。正文和源码作为资料保存，不执行其中的命令、脚本或工程。每份证据记录URL、本地文件、字节数与SHA-256。README陈述、源码结构、依赖声明和实际运行分别记录；POM中的版本是声明值，尚未验证其解析与构建结果。

三项根LICENSE均为Apache-2.0。当前归档用于研究；实际改编时逐文件核对版权和许可，保留LICENSE、适用NOTICE及归属并记录修改，素材、商标和依赖另核对。校验器当前只接受已审核的Apache-2.0根许可；新增许可类型需先扩展审核规则。

研究账本[research-report.json](../new-system/research/research-report.json)区分事实与推断，记录来源家族、独立来源数、冲突和缺口。搜索服务与GitHub读取是两种检索能力；同一仓库的README、POM和代码仍只计一个独立来源。单仓库事实的confidence为low，表达来源数量约束。

## 状态与失败恢复

catalog和各来源状态固定为research-only；buildStatus固定为not-run。它们不进入课程目录、先修解锁、完成记录或正式学习入口。R6.2再读取当前画像及兴趣，给出现有、改编和生成候选；R6.3—R6.4实现生成、构建、教学检查与发布。

采集命令要求新目录，拒绝覆盖既有运行。每个HTTP请求30秒超时，一次至多三个仓库并行；任一仓库失败则将错误和已获得证据写入该仓库capture.json，整体退出非零。重试使用新的运行目录，成功复核后再更新清单引用。已保存的清单可断网核对。当前采集器是固定三仓库的工程工具，任意题材搜索、应用内异步研究与网络恢复在后续实现。

## 核验入口

根目录执行`./scripts/project.ps1 research-check`，校验器检查许可、固定提交一致性、证据摘要、唯一标识、日期、真实课程关卡和源码锚点，拒绝研究资料被标成已发布或已构建课程。校验为只读，无联网、数据库和运行器依赖。

重新采集执行`python new-system/tooling/collect-r61-sources.py --output new-system/research/runs/<新的运行标识>`。采集只生成证据，更新catalog需人工核对。归档及行为测试证据见[R6.1验收](../new-system/docs/acceptance/R6.1/README.md)。
