## 主线

一个项目对应一份持续演进的工程、明确的业务目标和最终可运行产物。从最小必要配置开始，学习者亲手创建类、编写方法、增加功能、运行、修错、测试，直到完成该项目。章节是这个工程的开发阶段，不是相互独立的知识练习。每次讲概念，都要说明它解决当前项目的什么问题，以及接下来在现有代码的什么位置实现。

“从零”可以由系统提供固定运行配置、依赖和最小启动文件；不能默认提供已完成全部业务的代码，再仅要求改参数或修几个TODO，宣称从零完成。确需骨架、示例或参考实现时按需提供，并记录帮助程度。已有草稿继续保留，不因教学策略更新自动重置。

每章明确：当前项目已经做成什么、本章要新增什么、修改哪些文件、应该看到什么、运行反馈如何修正、下一章如何承接。进入下一章继续同一份源码，回看旧章只改变当前任务及检查规则，不把工作工程回滚成该章起步骨架。历史检查报告绑定当时快照；后续修改不改变历史证据。

选择题只作为概念理解与复习的补充，不承担主要学习过程，不阻挡有效代码检查后的完成和继续。代码检查、概念巩固、帮助记录与独立讲解分别表达；不能把完成编码说成已证明理解或独立能力。

## 所有项目的适配

| 项目 | 同一工程与最终产物 | 章节承接方式 |
| --- | --- | --- |
| HTTP/JSON入门 | 一个Java任务接口工程 | 最小HttpServer启动 → 编写首个响应 → 处理请求路径 → 状态与JSON → 运行追踪 → 完整功能检查 → 在本工程扩展笔记资源 |
| SQL任务数据实验室 | 一个任务数据数据库工程 | 连接、建模、查询、写入、分页脚本逐个加入工程；后续书签表是工程中的扩展。脚本可一起保存到同一目录，练习数据库保留；正式检查使用隔离数据验证当前脚本 |
| Spring Boot接口启动实验室 | 一个Boot工程 | 启动与健康接口 → HTTP控制器 → 分层 → 在已有工程接入JDBC；固定POM按运行阶段提供 |

| 兴趣改编及生成项目 | 每个题材一份独立工程 | 读取、校验新增与archive扩展都在同一份代码中实现；生成内容必须解释新增功能与已有工程的关系 |
| 独立作品C | 一份学习者设计的完整作品工程 | 需求设计 → 同工程核心实现与测试 → 陌生需求扩展 → 部署与开放讲解，继续保留真实回访 |

## 工程规则与验收

1. HTTP与固定Boot网页工程按项目共享源码和修订号；检查作业仍按课程版本及关卡绑定快照。不同项目隔离，多标签页旧修订拒绝覆盖。
2. 全新HTTP工程只提供HttpServer启动文件；项目A/B只提供固定POM与Application。后续章节不能自动注入已经完成的业务实现。历史发布课包保持字节稳定，原版骨架只作可选参考。
3. SQL采用同一工程内的多脚本文件，明确当前正在执行的脚本，保存目录包含已编写的工程脚本。不得把试运行当正式完成。
4. 生成项目共用项目级浏览器工程；切换章节、刷新和回看都保留源码。重新开始须说明会替换整个项目的当前源码，并确认；旧检查报告保留。
5. 代码完成接口验证报告、源码摘要、当前性、版本、策略、先修顺序及重复提交；不伪造答题记录。选择题可另行补充。
6. 验收必须实际执行“第一章写代码 → 保存/运行 → 下一章继续原代码 → 新增功能 → 回看原章仍保留最新代码 → 旧报告标旧 → 刷新恢复”。只展示步骤条不构成满足本要求。

## 本轮状态与边界

本轮实现工程接续、最小网页起步、实践步骤、可选概念巩固和代码完成入口，具体通过的测试、浏览器记录及待办写入`new-system/docs/acceptance/coding-first/README.md`。固定历史课包中的讲解与IDE骨架仍是旧发布版本；本轮网页采用新的项目主线适配。全部章节的讲解深度、每日一小时节奏及从零独立完成效果，仍需按项目逐章实际学习验收，不能由工程测试代替。

后续新增、修改、推荐、生成及验收项目时，以此文作为前置约束。先定义同一项目的最终产物和逐章代码增量，再组织知识点与补充题，不先堆知识题再拼项目。
