# 前端工作流与设计规范：六技能版

本规范替代本项目旧前端技能分工。全局只保存工作流；本项目视觉参数以DESIGN.md为准。

## 1. 六技能分工

| 阶段 | 技能 | 何时用、产物与边界 |
| --- | --- | --- |
| 方向探索 | Taste Skill：`design-taste-frontend` | 页面普通、缺乏视觉方向时研究构图和风格；适合展示类页面。已有明确控制台参考时无需重新抽风格。 |
| 方向探索 | `frontend-design` | 没有明确风格时依据内容建立方向。同一轮与Taste二选一。 |
| 多页面体系 | `ui-ux-pro-max` | 统一导航、布局、表单、组件状态、响应式与变量；检索结果须核对适配性。 |
| 中期调整 | `impeccable` | 针对具体问题选择critique、bolder、quieter或polish，保留锁定的方向。 |
| 细节手感 | `make-interfaces-feel-better` | 圆角、光学对齐、数字跳动、换行、阴影和可中断动效；使用Jakub Krehel版本。 |
| 交付检查 | `web-design-guidelines` | 按实际范围检查按钮、表单、焦点、响应式和语义，再结合浏览器走流程。 |

每次任务先判断目的和阶段，使用前点名并读取对应技能。一次可只用一项；不因有六项而生成六轮重复评审。浏览器与截图工具属于执行手段，不计入六套设计技能。

## 2. 本项目的执行顺序

**参考拆解。** 先打开ElevenLabs图库指定页面，记录布局、主次、间距、组件及交互。按桌面参考分析，不把截图像素尺寸等同CSS视口。素材未覆盖的状态用产品需求设计并标为适配。

**设计系统。** 使用UI/UX Pro Max补齐应用导航、表单、状态和多尺寸规则。只采用匹配项。初次检索`developer learning dashboard`给出宣传页结构、儿童字体和教育配色，已否决；缩小为`navigation deep linking`后采用URL反映页面状态、固定导航不遮挡内容、键盘焦点顺序三条规则。

**实现。** 先做真实学习工作台与续学入口，以真实课程、错误与报告验证布局，再扩展项目库、复习和画像。公共组件共享变量和交互契约，不为每页建立独立按钮体系。

**中期。** 首次可运行后用Impeccable评估层级；过密时处理quieter，主次不足时处理bolder，结构稳定后polish。评估应指出具体页面、问题与修改结果。

**细节。** Make Interfaces Feel Better检查嵌套圆角与边距、图标视觉中心、长标题、按钮等待状态、等宽数字、浮层阴影及可中断动效。只调整实际问题，不为演示动效加入新框架。

**验收。** web-design-guidelines按当时官方规范读取并检查新代码；浏览器按docs/03的断点及真实任务验收。每轮先修布局与字级，再修颜色、间距、组件；复用同轮证据，只复查受影响处。

## 3. 参考适配规则

保留ElevenLabs的灰白色阶、固定侧栏、轻边框和编辑/辅导分区。2026年11月11日用户明确要求更多颜色且可大胆创新，0.8.0主操作由黑色改为钴蓝，并以青绿、杏橙、淡紫承担知识/预期、提醒和练习角色，具体变量见DESIGN.md与design-system.css。移除音频业务、活动横幅与无关导航。学习路径不用宣传页英雄区、海报拼贴或滚动叙事。

截图是布局研究材料，避免把含账号信息的整图作为产品背景；公开分享时重新脱敏并检查。字体和组件可采用合法成熟实现，统一来源与版本。

2026年11月10日补充：用户明确要求采用LeiBox与shadcn/ui作为组件来源。当前主视觉不变，按实际用途选取并适配，保留原始来源、许可证或声明；先查项目COMPONENTS.md复用已接入组件，再按需检索。避免把组件演示页布局、假数据或无业务用途的装饰一起带入。

## 4. 抖音作品采用要求

FR01 结构与层级解释主要操作。FR02 清理重复解释和装饰文案。FR03 次要帮助按需展开，触屏和键盘也能使用。FR04 保留标签、可访问名称、错误原因和重要后果。FR05 动效服务状态反馈，减少布局抖动并支持减少动态效果。FR06 课程正文、示例、练习与概念解释完整提供。

来源为小石谈记（AI版）《怎么让codex设计前端更优雅》，详见[来源说明](references/douyin/作品内容与采用说明.md)。视频中的工具或模型偏好不替代当前项目工作流；六技能清单来自用户本次明确要求。

## 5. 组件契约

按钮：正常、hover、focus、pressed、disabled、loading。提交中保留宽度，防重复请求；禁用原因可理解。链接用于跳转，按钮用于动作。

输入：可见标签、关联说明和错误；保留用户值；错误后可定位字段。成功与失败不只靠颜色。

面板：标题、关闭、返回焦点、必要的滚动边界。模态对话限制焦点，非模态侧栏不误设模态。破坏性操作显示实际对象与后果。

课程：语义标题、可复制代码、示例输出、正文层级；代码长行局部滚动，行号不进入复制文本。报告：状态、原因、证据、期望/实际和重试路径。

状态：骨架保持尺寸；长任务有开始/进行/完成/失败/取消；toast用于短反馈，关键错误保留在页面。流式回答不自动抢焦点。

## 6. 交付证据

每阶段在`new-system/docs/acceptance/Rx/`保存构建与核心测试结果、相同视口截图、主流程检查、问题修复记录。检查键盘、200%文字放大、长内容、加载/空/错状态及减少动态效果。

报告注明实际检查页面、尺寸、浏览器和结论。设计文档完成、代码完成、运行通过、浏览器通过是不同状态，分别记录。
