# 本地运行优先与检查环境回退

2026年11月17日用户确认：学习项目优先在本机编译、运行，由网站检查本地运行结果；本地环境不可用时使用备用虚拟环境。本规格覆盖docs/28及早期文档中“所有提交统一在Docker编译”的执行方式。

## 运行规则

HTTP检查从编译输出发现 `TaskServer.class` 并按其完整类名启动，支持有包名和无包名的 `TaskServer.java`。源码缺少启动入口时，报告提示添加 `public static void main(String[] args)` 并启动HTTP服务。本机编译和运行进程以UTF-8输出日志，保留Windows中文诊断。需要回退时，Docker使用相同的入口解析规则；两种环境均无法执行时，报告列出各自的原因。

HTTP入门、Boot启动/HTTP/分层章节和生成项目优先使用本机JDK及Maven。检查仍验证真实HTTP状态、类型、字段和业务行为，不能以终端输出或启动成功替代功能检查。

浏览器FileSystemDirectoryHandle不会提供本机绝对路径。网站继续保存当前磁盘源码为不可变提交，本机服务在runtime/data/local-runner内按工程会话维护快照构建目录；不要求用户重新手填路径，不修改原始学习工程，不接管或关闭IDEA进程。检查服务亲自启动本次编译的程序，避免误连IDE内的旧版本。Boot使用随机回环端口，HTTP课程保留约定的8080；8080被占用时保留占用进程，转入备用隔离检查。

复用本机Maven仓库。相同HTTP源码可复用已核对摘要的class；源码/POM/资源发生变化时清理私有编译产物后重新构建，避免已删除类、资源及旧JAR继续影响报告。原POM、包名、启动类和JAR名称继续保留。报告绑定原快照摘要，完成前磁盘核对及过时判断沿用既有规则。

## 回退条件

本地缺少JDK/Maven、依赖解析或下载失败、本地端口不可用等基础环境问题触发备用检查，并在报告中记录原因。编译错误、应用启动错误、接口业务不符、检查超时和用户取消直接反馈，不通过换环境掩盖学习结果。本地进程结束后才能进入备用环境。

Boot JDBC、项目A/B、SQL和独立作品中需要数据库重置、权限、事务、并发及持久性验证的章节继续使用隔离环境；不向用户真实学习数据库写入测试种子或执行清理SQL。Tlias仍为资料实战，本轮不新增自动判题。

备用环境是已有的本机Docker隔离环境；当前没有新增云端服务、上传路径或计费依赖。后续若接远程运行服务，必须另外实现身份、上传范围和服务配置，不能把本机Docker称为已上线的云端环境。

## 进程与报告

编译和应用进程均受取消与超时控制；服务关闭时停止本次创建的进程及子进程。持久记录PID、启动时间和工作目录，重启时同时核对启动时间与命令参数再清理，防止PID复用时停止其他进程。原学习工程及IDE内运行中的应用不受清理影响。

进度条反映本机准备、编译、启动、检查和整理的真实阶段；进入备用环境时重置为准备阶段。报告使用local-jdk标识本机执行，隔离报告保留原镜像ID，并增加回退原因。课程版本、功能通过、概念验证、完成与学习画像规则保持原有定义。

## 配置

默认cs.runner.local-enabled=true；可用同名Spring命令参数切回隔离优先。cs.runner.local-java-home默认服务所用JDK；cs.runner.local-maven-home优先指定配置，否则读取CS_MAVEN_HOME，再使用本机现有Maven路径。cs.runner.local-repository、cs.runner.local-settings可指定现有仓库和settings.xml；默认优先复用用户.m2/repository及已有settings.xml，无对应内容时分别使用runtime/maven-repository和tooling/maven-settings.xml。cs.runner.local-timeout-seconds默认120秒。

此流程面向当前本机单用户部署。本机执行会运行所提交工程的构建及Java程序，不能直接将该配置作为允许陌生人上传代码的公开运行服务。

工程证据、耗时样本与交付状态见new-system/docs/acceptance/local-first-runner。
