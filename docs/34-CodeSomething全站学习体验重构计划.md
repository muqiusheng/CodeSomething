# CodeSomething全站学习体验重构计划

2026年11月19日 · 实施提案

## 1. 重构目标

让第一次做Web项目的人从「看到一个网页效果」走到「用自己的Java代码做出这个效果」，此后每天打开网站都知道要继续哪一步、改哪个文件、怎样确认做成了。直到作品阶段，网站始终围绕学习者自己的工程、可运行结果和讲解证据组织。

重构覆盖全站导航、学习首页、课程与项目目录、教学和工程工作台、复习画像、兴趣项目、作品与设置。首条切换链路是「首次进入 → 看懂接口效果 → 写出第一份Java程序 → 同一工程返回真实HTTP响应 → 第二天从原位置继续」。其他项目随后按已验收的界面和交互契约迁入。

按已确认的产品定位，主用户有Java基础、第一次做Web后端。Java薄弱时按当前卡点补练。首页说清最终产物是一份能运行、能测试、能讲清的后端项目，提供的网页用来呈现接口效果。每个项目从自己的最小工程开始，逐章增加功能。同一项目换章、预览及回看始终使用原工程目录。完整前端路线、完全零编程路线和公开云端运行分别作为后续产品决策。依据见[产品定位](../PRODUCT.md)、[同工程教学原则](25-同一工程从零完成的项目教学原则.md)和[逐课课表](33-Java后端全流程逐课课表.md)。

## 3. 全站页面与职责

主导航建议统一为「学习」「学习路径」「项目」「复习」「作品」，个人中心与设置从头像进入。保留既有URL和深链接。学习路径的七阶段概览、原项目开发路线和正式关卡、项目列表「展开课次」继续可用，逐课任务从这些入口直达同一个学习位置。

| 页面 | 用户要解决的问题 | 首要内容及动作 |
| --- | --- | --- |
| 学习首页 `/learn` | 我今天做什么 | 首访进入第01节。在学直达明确的课次或步骤。显示当前工程、今天交付的结果和下一步。演示与准备提示跟随首次学习，复习与探索降到次级 |
| 学习路径 `/path` | 学这些内容最后能做到什么 | 每个阶段给出工程产物、当前进展和需要的先修。展开查看课次。72节主线与18节补练/选修用同一课表数据呈现 |
| 项目库与详情 `/projects` | 选哪个项目，怎样做完整 | 列表保留搜索、收藏及原地展开课次。详情先展示业务效果、工程路线、环境和开始/继续。Tlias标明运行与验收方式，生成项目展示自己的验证状态 |
| 逐课页与关卡工作台 | 这一阶段改哪里，运行后看什么 | 课次、任务与工作台相互直达并保留来源。桌面左边读教学和步骤，右边编辑或查看工程，结果靠近代码。窄屏提供明确的教学、代码、结果切换 |
| 复习 `/reviews` 与个人中心 `/profile` | 哪些会用，哪些还要重练 | 到期项目给出推荐依据与「开始复习」。用户可做、稍后或主动选择。画像中的能力可追溯到实际报告、帮助及回访 |
| 作品 `/portfolio` 与兴趣工作室 | 怎样交付自己的作品，换题后能否独立做 | 作品沿需求设计、工程检查、开放讲解、回访推进。生成候选说明能力依据、验证状态及接入路径；暂停或失败后能回到草稿 |
| 设置 `/settings` | 如何处理环境、AI、偏好与数据 | 设置提供全局诊断与配置。课程当下的故障从原位置就近处理，完成后回到原课及步骤 |

视觉上沿用已有控制台、力扣式编程分区及Cupcake/Synthwave双主题。重构先锁定页头、阅读宽度、分栏、操作区、状态提示、焦点和移动端切换规则，再统一各页面。首屏固定一项主动作，正常教学内容保留完整表达。术语以「原名＋一句说明」出现，详细解释可点击或通过键盘查看。参考与组件决策写入DESIGN.md和相关规格。

## 4. 关键交互与工程规则

### 4.1 首访、续学与跨页面返回

- 首访有可靠的空状态时进入第01节。大纲、项目详情和补练仍可预览。首个演示用正确JSON和任务卡片显示示例数据如何影响界面，体验后直接开始实操。
- 开始或明确继续主线后记录课次和来源。正式工作台记录项目、课程版本、关卡与有效步骤。课次进入对应工作台后，返回操作带回同一课次。直接从项目进入正式关卡时按项目会话续学。
- 由共享的下一步解析规则比较有效的主动学习位置。最近明确打开的学习目标优先；只有旧记录时优先恢复有效正式任务，浏览器课次提供回退入口。新记录从显式学习动作取得时间与来源，旧记录缺时间时按兼容优先级处理。预览、补练、历史报告和失败请求均不覆盖主线位置。
- 当前流程通过后，根据映射显示相邻课次或关卡。课次验证、正式通关与能力证据各按已有规则记录。加载中保持当前位置提示，加载失败给重试和目录入口。离线正做的课次可继续阅读，恢复后核对进度。

### 4.2 课程与初次动手

每章的顺序统一为「已有工程成果 → 本章增量 → 文件和修改点 → 运行 → 预期结果 → 常见错误 → 承接下一章」。用现有的前六节打磨教学样板。

1. 第01节在自己的目录里建Java文件，运行并看到自己写的句子。已有环境的人直接运行。环境未就绪时，显示所需项、可用检查结果和对应修复步骤。
2. 第02节继续同一文件，让浏览器收到自己写的文本。分别显示「预期响应」「本次真实结果」与「正式检查状态」。初次只解释URL、请求和响应的实际关系。
3. 第03–06节观察请求日志、练习启动和停止、连接原目录、修复一次入口错误。第06节后继续用同一工程做JSON和任务接口。
4. SQL、Boot、A/B各以自己的真实业务增量形成对应样板。先完成路径映射和课次交接，再按样板补齐具体讲解；对72节主线校验任务、文件、执行方式和结果，对18节补练校验回原课。

### 4.3 运行、保存与辅导

- 操作分清「保存源码」「运行查看结果」「提交正式检查」。有真实运行能力的课次才显示运行入口，示例和手动运行章节标清反馈来源。提交沿用不可变快照、真实执行器和既有通过规则。
- 显示目录未连接、授权失效、文件缺失、网页未保存、IDE冲突、排队、运行、失败、历史通过、当前代码已变化等状态及下一动作。保留网页草稿和磁盘内容，冲突由用户核对。报告在重新连接、刷新和任务继续运行后恢复到原作业。
- 统一结果区结构。先展示结果及原因，再显示预期和实际、相关文件或接口，原始日志可展开。报告绑定原快照；后续源码变化时为旧报告标记时间与当前性。
- 教学页就近提供AI。先用确定性错误或课程提示帮助定位，再使用现有「概念提示／定位问题／示例讲解」等级。学员可见发送范围并按原规则选取代码或报告。AI不可用时可继续读课、保存、运行和检查。

### 4.4 低门槛体验与免安装决策

基础交付提供可直接操作的接口演示，并优先改善本机开工。工作包A记录有无JDK两类首次体验的实际卡点，核对诊断能力与可行的运行方式。若试学反复卡在安装且短引导无法解决，再把免安装实操列为独立实施包。试点须同时证明真实Java执行、可控资源边界、同一份源码可交接到本地、错误可恢复及真实证据兼容。编辑器仅解决输入，模拟只能用于教学演示。新增托管成本和运行方式需单独决策。

## 5. 工作包、依赖与验收

下面按单人顺序实施估算有效工作日，包含该包测试与修正。有效工作日以本机已有基础和主要契约复用为前提。A结束后用实际结果重估，隔天回访另占自然日。

| 工作包 | 估算 | 前置 | 主要交付与验收 |
| --- | --- | --- | --- |
| A 基线、信息架构与兼容清单 | 2–3日 | 当前版本 | 盘点页面、课次、正式关卡、查询参数和报告深链接，建立现状截图和新旧入口映射。用空进度、历史进度、已绑定工程和本地草稿四类样本记录现状。交付导航与三类页面线框，核对复习请求与本机环境卡点 |
| B 应用壳、首页、路径、项目 | 3–5日 | A | 统一导航和下一步入口，前置示例；让课表、路径、项目和正式任务直达。首访只出现一个主学习动作；已有进度直达正确任务；预览或刷新不改变主线；90节链接及项目原有目录均可达 |
| C HTTP入门与共享工作台 | 4–6日 | A、B中的路由规则 | 打通第01–06节、运行结果、报告和正式关卡回链。真实作业完成一次成功、一次失败修复、跨章增加功能、回看旧章和隔天重开；目录确认实际走系统窗口，既有IDE和网页修改能恢复 |
| D 各课程与高级工程接入 | 5–8日 | C | 按SQL → Boot → A → B → Tlias与生成项目接入。每类给一次真实正反例或其适用的独立运行验收，保留专属能力。检查72节主线的任务交接和18节补练的返回；原有正式通过规则与历史报告可查 |
| E 复习、画像、作品、设置 | 3–5日 | A、B、C的状态契约 | 复习空白、离线与重试各能恢复。画像引用实际证据，作品C从设计到真实工程检查、讲解和回访走通。模型不可用时仍可做课。课程跳诊断后回原步骤 |
| F 综合回归、试学及默认切换 | 3–5日 | B–E | 比较现有站点与新版主任务路径，回归双主题、键盘、移动端、历史URL、并发保存和服务恢复；真实试学验证首启、出错修复、次日续接。记录发布产物与回退演练，切换后复验日常数据 |

总计约 **20–32个有效工作日**。第一个完整的新版入门流程在A–C完成后可供试学，约 **9–14个有效工作日**。D的主要变量是逐课内容不一致和各执行入口差异，F的主要变量是恢复问题与真人反馈。公开云端运行和免安装实操另估。

## 6. 验收矩阵

| 场景 | 可以观察到的结果 |
| --- | --- |
| 首次进入与首次开工 | 确认用户能说清项目做什么，无需口头指路即可进入第01节。第01节真实输出，第02节同一Java文件改句后一致返回。记录配置、学习和排错各自耗时 |
| 正式任务与代码连续性 | 同一工程继续新增功能；回看旧章文件内容不回滚；旧报告可打开并标明对应快照；重启后台或刷新页面可恢复原作业。一个错误变式得到明确失败提示 |
| 现有用户切换 | 已有课程和版本链接正确跳转，已保存的工程连接、网页草稿、报告、复习、作品和已完成记录可使用。故障恢复走现有支持的连接方式，并保留原工程 |
| 能力与学习效果 | 学员能指向Java里返回正文的位置，能解释一次自己的错误；记录使用的帮助级别。隔天能从明确的续学动作回到同一项目。首轮按实际样本报告每个卡点，留存目标有基线后再设 |
| 异常与中断 | 课程读取失败、复习请求失败、断网、权限失效、目录取消、编译错误、运行超时、AI停止分别有对应状态与可执行下一步 |
| 可访问与响应 | 双主题，320/375/768/1024/1440宽度及200%放大抽查。键盘可到主要动作、分栏、代码与报告。浮层归还焦点，固定操作条不挡内容，代码等长内容仅局部滚动 |
| 页面与数据切换 | 预览版与日常数据隔离，使用数据副本和临时学习目录完成切换演练。比较已有记录标识和代表性数据，真实工程文件未被界面切换改动 |

工程验收复用现有前端单元、生产构建、浏览器脚本与后端专项，新增覆盖下一步规则、历史路由及有实际风险的恢复。优先复用 `check-full-journey.mjs`、`check-first-program-and-completion.mjs`、`check-project-continuity.mjs`、`check-ide-save-sync.mjs` 与原生连接脚本。学习验收记录「是否独立完成、卡点、帮助层级、隔天续学」。报告中分别写工程测试和真人试学结论。

## 7. 兼容、发布与回退

1. 在`new-system/`复用现有前端、后端、运行器和发布门禁。首批优先改导航、位置解析和展示层。用路由与状态适配读取现有课程、提交和进度，避免为换界面更换课程ID或重建历史记录。
2. 基线盘点明确保存位置。数据库、课程发布文件、本机连接索引、浏览器localStorage/IndexedDB及会话草稿分别演练。隔离预览使用独立端口和数据副本；同源相关的草稿与授权另在目标Origin的隔离浏览器配置演练。新版兼容读取原键与原数据，不要求学习者重建目录。确需新增数据时优先采用可兼容读取的增量变更并演练旧版恢复。
3. 每包先验证后切流。记录旧、新前端包及后端配套版本，切换前备份日常数据并检查活动作业；运行中的检查完成后再切换。上线后用同一真实用户路径核对续学、保存、运行和已有历史证据。
4. 路由或界面故障优先恢复上一版发布产物并保留期间新增的学习记录。若数据变更影响兼容，先保全切换后的数据和用户工程，再依据已演练方案恢复。避免用旧备份直接覆盖期间的新进度。以无法续学、代码保存受阻、历史证据无法读取或正式状态错误为回退触发条件。

## 8. 首批执行顺序

1. 建立当前站点基线，复现或排除附件中的复习404，实测一次从空进度开始，并演练已有记录和本机工程恢复。
2. 定稿「首页—第01课—工作台—第02课—隔天续接」的路由和界面草图，同时画出课次、正式证据和项目目录的连接。实现之前先写下一步状态规则和新旧入口映射。
3. 构建应用壳与首页，随后交付真实入门样板。在这条链路通过工程验收并取得首次试学反馈后，把约定推广到其他课程和辅助模块。

本文件提出重构范围、默认技术选择和估算。实际实施结果、截图、试学和待解决项在对应工作包完成后登记到[实施追踪](实施追踪.md)及验收目录。
