# Java后端全流程逐课课表

2026年11月19日。面向学过Java基础、接触过少量数据库、第一次做Web与Spring Boot项目的学习者。承接[全流程调研](32-零Web基础到独立后端作品的学习流程.md)和[同一工程教学原则](25-同一工程从零完成的项目教学原则.md)。本稿确定课次、代码增量、结果和参考资料，供课程制作与真人试学。

## 课时与学习方式

主线共**9个模块、72节**，另有**18节选修和补练**。每节主线以约35–60分钟设计，做完一个可运行的增量即可停下。首次安装、下载和个别排错另计。每个项目从自己的最小工程开始，后续各节在同一份代码上修改。项目B的工程继续用于交付模块。作品C由学习者自主选题并创建新工程。

正式制作每一节时，页面按顺序给出当前工程状态、具体文件和代码锚点、一个动作、运行方法、预期结果以及常见错误。第一次做时给逐行示范，第二次给位置和提示，第三次给新需求与验收条件。学习者完成的是自己工程中的修改。阶段最后一节留出一次新输入、小改动或复现练习，用于决定先补哪一块或进入下一阶段。

菜鸟教程作为中文查阅资料。每节使用对应段落和实际练习，课程说明、代码任务、预期与排错独立编写。框架版本、工程配置、密码处理和部署命令以当前项目及官方文档校对。

## 1. 从空文件到第一次浏览器响应 · 6节

使用自己的HTTP练习目录和根目录`TaskServer.java`。入门操作在本模块做完，后续章节直接从已有代码开始。 [菜鸟教程 · Java方法](https://m.runoob.com/java/java-methods.html) · [菜鸟教程 · HTTP消息结构](https://www.runoob.com/http/http-messages.html)

| 课次 | 在自己的工程里做什么 | 看到什么才算做完 |
| --- | --- | --- |
| 01 | 在IDEA新建Java工程和`TaskServer.java`，输入`main`，打印自己选的一句话。 | 通过绿色运行按钮在控制台看到原句，知道文件名和运行入口在哪里。 |
| 02 | 在第01节的文件中按讲解加入最小HTTP启动代码，亲手写返回文字的方法。打开课程给定的本机网址。 | 浏览器显示自己写的文字。改一句并重启程序，页面显示新句子。 |
| 03 | 重复访问第02节的地址，在处理请求的位置加一行控制台输出。 | 点一次刷新就新增一条请求日志，能把网页变化指回Java中的一行。 |
| 04 | 学会停止、启动和重新加载。对同一个网址分别访问已启动和已停止的程序。 | 能识别浏览器连接失败，并通过重启恢复响应。 |
| 05 | 保存文件，选中工程根目录，在网页工作区打开该文件，再把IDE改动同步过来。 | 在网页看到IDE保存的新内容，能解释保存、运行和提交验证各是什么动作。 |
| 06 | 在练习副本中按要求把入口改坏一次，读报错并修回。 | 能指出`main`的位置，程序恢复启动，并再次看到自己的浏览器响应。 |

## 2. HTTP与JSON任务接口 · 8节

继续第06节的`TaskServer.java`。从已会运行的接口扩展到成功与失败两条请求链。 [菜鸟教程 · HTTP请求方法](https://m.runoob.com/http/http-methods.html) · [菜鸟教程 · HTTP状态码](https://m.runoob.com/http/http-status-codes.html) · [菜鸟教程 · JSON语法](https://m.runoob.com/json/json-syntax.html)

| 课次 | 在自己的工程里做什么 | 看到什么才算做完 |
| --- | --- | --- |
| 07 | 改处理器注册的路径，用新地址请求一次。 | 能在地址和代码里指出对应的路径，能解释端口和路径各选什么。 |
| 08 | 读出一次GET的请求路径，用Java的`if`区分任务1与任务2。 | 两个网址走进不同分支，控制台留下不同记录。 |
| 09 | 把成功分支的一句话换成有编号、标题和完成状态的JSON。 | 浏览器看到三个字段，说得出数字、字符串和布尔值分别长什么样。 |
| 10 | 给带中文的JSON设置响应格式，按UTF-8转换后写出内容。 | 中文可读，在浏览器网络面板能找到`Content-Type`和响应正文。 |
| 11 | 给存在的任务返回200，给找不到的任务返回404。 | 网络面板显示两种状态，未知任务附可读说明。 |
| 12 | 在练习副本里故意把布尔值写成带引号的字符串，读检查结果后修复。 | 能指出预期与实际类型的差异，自己重跑验证。 |
| 13 | 在已有处理器中给另一条任务定义不同标题，保留已经做好的路径和错误返回。 | 改动前后的两条请求都能复现，能指出自己动了哪几行。 |
| 14 | 从现有任务处理方式出发，新增一个按编号读笔记的路由。 | 任务仍可访问，笔记有成功和未找到两条真实结果。 |

## 制作样例与发布核对

**第02节示例。** 从第01节已有`main`且能打印文字的版本开始。以下是新建默认包练习工程的完整示范。已有自己的包名时，将原`package`声明保留在文件最前面。

```java
import com.sun.net.httpserver.HttpServer;
import java.io.IOException;
import java.net.InetSocketAddress;
import java.nio.charset.StandardCharsets;

public class TaskServer {
    public static void main(String[] args) throws IOException {
        HttpServer server = HttpServer.create(new InetSocketAddress("127.0.0.1", 8080), 0);
        server.createContext("/api/tasks/1", request -> {
            byte[] message = taskMessage().getBytes(StandardCharsets.UTF_8);
            request.getResponseHeaders().set("Content-Type", "text/plain; charset=utf-8");
            request.sendResponseHeaders(200, message.length);
            try (var output = request.getResponseBody()) {
                output.write(message);
            }
        });
        server.start();
        System.out.println("服务已启动： http://127.0.0.1:8080/api/tasks/1");
    }

    static String taskMessage() {
        return "我的第一个任务接口";
    }
}
```

1. 在文件开头补齐`import`，按示范修改`main`，在`main`下方手写`taskMessage()`。本节先记住这个方法负责决定浏览器看到的文字。请求处理器的细节在HTTP模块继续拆开讲。
2. 点IDEA里`main`左侧的绿色运行按钮。看到控制台「服务已启动」后，打开`http://127.0.0.1:8080/api/tasks/1`。预期看到「我的第一个任务接口」。
3. 把返回值改成自己的一句话，停止旧程序，重新运行再刷新。看到新文字时，检查自己是否能指出决定结果的那一行。
4. 浏览器无法连接时，先看IDEA控制台有没有启动提示。提示`8080`被占用时，先确认上一份练习服务是否仍在运行。出现缺少`main`的提示时，回到第01节核对入口。网页正式验证按现有课程契约执行，本节以真实浏览器里显示自己的文字为学习证据。
