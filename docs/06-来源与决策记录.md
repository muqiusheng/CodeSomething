## 4. 新方案的工程提案

D01 前后端分别采用React/TypeScript/Vite与Java/Spring Boot，理由是操作型多页应用需要共享状态组件，后端课程又以Java为主。技术版本和组件库在R1核实锁定。

D02 采用本地平台存储与独立课程数据库，避免学习环境重置破坏进度。SQLite驱动与迁移方案在R1验证。

D03 首个题材用个人任务管理，能力迁移清楚、规模可控；题材可按兴趣调整。

D04 新工程放new-system，旧code-something保留原样。新课程ID、状态与API独立，旧数据不自动导入。

D05 真实编码先通过最小桥接闭环，再做IDEA插件，先验证教学而不是先投入完整插件。

D06 画像优先采用可解释规则和证据等级，收集真实学习数据后再校准。

## 8. R2.1—R2.2决策（2026年11月11日）

首个HTTP/JSON任务采用JDK21自带HttpServer的完整单文件骨架，避免在尚未教授Spring Boot时要求先创建Spring工程。只修改两个业务TODO，保留后续Spring Boot课程和项目A目标。HTTP材料依据MDN HTTP Overview（https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Overview），JSON材料依据RFC8259（https://www.rfc-editor.org/rfc/rfc8259），本轮已实际查阅；正文为项目自行编写。

快照只有TaskServer.java且最大64KiB，因此先将源字节与元数据同SQLite事务存储，减少外部文件双写失败；日志与运行产物仍由R2.3放runtime/artifacts。配对预览带5分钟单次码，绑定令牌限定目录和课程范围，API校验本机Host/Origin；当前标签页恢复提交，未实现全生命周期撤销。未来IDE桥接扩展此协议，不复用旧项目实现。
