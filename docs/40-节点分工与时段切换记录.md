1. 在上海新目录接收并恢复一份主站生产备份。为同一批次核对 SQLite、MySQL 快照、双镜像、部署和加密配置、课程包及校验清单。复用现有 `peer-backup.py restore-check` 校验 SQLite，再从隔离 MySQL 导入实际快照。使用专用测试学员核对会话、SQL 草稿与进度记录。保留原上海备份及 `maqibu` 现用备份路径。确认上海自动收到下一批完整归档后，再移交备份职责。上海仅用于备份和手动恢复。
2. 判题先选 HTTP/JSON 课程 1.1.0 工作区章节的 Java 控制台检查，复用 `ConsoleOutputCheck` 和网络隔离的 `DockerCheckRunner`。主站保管已有提交快照与结果，按提交 ID 幂等，给领取者有截止时间的租约。结果保存必须同时匹配提交和当前租约，并与写入最终状态在同一个 SQLite 事务里完成。掉线后过期重排，拒绝已经失效的执行结果。私有通道仅接收领取和返回结果操作；到点停止领取，开放时间内领取的任务可在有效租约内回传。暂未接入线上。
3. `maqibu2` 先核对实际套餐、可用磁盘、构建所需空间和持续运行记录，再接构建与打包。MySQL 仅先为专用测试学员开放，完成一次保存和隔离恢复后再评估现有学员实例。主站保留账号、会话、草稿、进度和判题结果的唯一写入权。判题节点不可用时显示排队，MySQL 节点不可用时仅相关练习显示暂不可用，登录和草稿走主站。

管理 API 当前凭据只可见 `maqibu`。查询时返回免费档、4 vCPU、8 GiB、16 GiB 系统盘配额、20 GiB 持久盘配额、120 分钟运行限制、1800 秒自动休眠设置，状态为 `running`，`cooldownUntil` 为空。该查询不代表宿主实际磁盘余量。已发现用户打开的两个 Chrome 管理窗口，桌面控制因无法可靠识别浏览器地址而停止。上海已有部署密钥可加载，私用域名的 DNS 指向回环地址，实际 SSH 入口待接续。

## 11 月 26 日晚间课堂容量实测

在真实三台主机的服务时段内，使用当前生产后端镜像、隔离 SQLite 和专用测试学员压测。公网测试从一个网络经 Cloudflare 访问 `try.maqibu.online`，复用一个现网测试学员。在主站同机的隔离后端使用不同账号，逐人核对读回的草稿，隔离副本沿用生产的 1.5 GiB 容器内存上限。压测客户端使用 Python，在固定时间发起操作，同时统计错误、业务结果及第 95 百分位耗时。下列耗时分别标明公网或后端。

| 场景 | 压力与结果 |
| --- | --- |
| 公网读实验题 | 50 个客户端分散请求。每秒 10 次档 300/300，每秒 12.5 次档 750/750，每秒 15 次档 500/500。三档 P95 分别为 0.94、0.91、1.02 秒。升至每秒 18 次时，在 9.33 秒内有 162 次成功、1 次 HTTP 429，随后停止。 |
| 同时点开题目 | 50 个公网客户端同时新建连接，46 次成功，4 次 HTTP 429。成功请求 P95 为 3.19 秒。生产 Nginx 限速按其观察到的来源地址计算，每秒 15 次，可短时突发，另有限制同时连接数的规则。 |
| 独立学员保存草稿 | 50 名学员每人每 12 秒读题、保存和读回一次，共 5 轮、750 个操作，全部成功，逐人读回自己的内容。服务端附近测得读题、保存、读回 P95 分别为 67、18、13 毫秒。65 人短测 2 轮共 390 个操作，全部成功。 |
| SQL 实例边界 | `maqibu2` 上为本轮建立另 15 个独立的 384 MiB 测试盘位，配置与生产相同。15 个测试学员各自首次启动并判得 10/10，单次 5.73–7.16 秒。第 16 名得到 `unavailable`。15 人占位时让 50 个不同学员同时提交，15 份得满分、35 份返回暂不可用，最后一份响应在 12.93 秒返回。 |
| 真实公网 SQL 交卷期间存草稿 | 一个现网测试学员在不同实验并发交卷。2、3、4 题三档均实际判为满分。同时保存另一份草稿耗时分别为 0.28、0.83、4.59 秒。4 题档最后一份成绩在 5.25 秒返回。一个单独样本耗时 6.75 秒。生产实现的课内实验判分与草稿保存共用控制器同步锁。 |
| 50 人同时提交基础 Java | 50 个独立学员各提交一份具有不同输出的程序。主站同机隔离副本全部接单，入队请求 P95 为 239 毫秒。在真实 `maqibu` 使用现网同一 JAR 与 Docker 镜像，独立工作进程通过临时私有端口向隔离主站领取任务。50 份全部通过，逐份校验输出。提交到成绩的中位数 118.6 秒，P95 为 198.7 秒，最后一份 209.8 秒。测试端按生产 15 秒周期、每次最多 4 份发送通知，首批与第二批之间包含测试驱动接续时间。生产公网专用学员两轮均为两份接单通过，同一学员在前两份尚未结束时再提交，第三份收到 HTTP 429 `RUNNER_BUSY`。 |

公网的 50 个客户端测的是一个来源的网络、网关及读题响应。独立账号测试测的是已登录学员的实际操作，跳过了公网链路。一台机器模拟客户端也无法代表不同地区和校园网的延迟。每分钟每来源最多 5 次登录、5 次注册，隔离环境的同来源集中注册实际触发了 429，测试学员按允许的速度准备。测试覆盖 HTTP/JSON 控制台和本轮课内 SQL 题型，其他课程、完整考卷和整节课时长仍需各自测量。


独立学员数升至 75 人时，2 轮共 450 次操作全部成功，保存 P95 为 1.16 秒。该档与另一组 SQL 压测的时段有重叠。75 是此次主站读写实际测到的人数，公网网关和跨机执行仍各自有限额。

混合课堂采用 50 个独立学员每 12 秒读题、保存和核对草稿一次，由其中 15 个已有实例的学员提交同一道练习题。两分钟以每分钟 40 次的节奏共判 80 份，全部满分。1,500 个读写操作均成功，保存 P95 为 0.47 秒，判题 P95 为 0.64 秒。短时档以每分钟 80 次运行约 36 秒，48 份全对，保存 P95 为 0.55 秒。以每分钟 100 次发起时，未结束的判题达到 6 份，停止继续加压，已发出的 54 份全部完成，判题 P95 为 5.39 秒，保存 P95 为 5.11 秒。以上为预热实例重复该题的服务端附近耗时。换题、冷启动和公网传输会影响学员实际等待时间。[分档原始计数与延迟](../new-system/docs/acceptance/capacity-20261126/classroom-capacity.json)

测试完成后移除了两侧隔离后端、临时 Java 工作进程、私有端口、测试数据库、会话文件和 15 个测试盘位。主站生产后端健康，生产 Java 和 MySQL 执行服务处于活动状态，MySQL 仍有 15 个生产盘位，执行节点数据盘可用 8.5 GiB。现网专用学员的验收成绩保留。此轮仅测容量，未调整生产限流、池大小或管理员凭据。
