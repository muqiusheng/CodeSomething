# R2.4 双结果完成与续学计划

日期：2026年11月11日。状态：R2.4实现与验收已完成，任务状态见实施追踪，实际证据见new-system/docs/acceptance/R2.4/README.md。以下保留实施契约。

## 目标与基线

让学习者完成一次可恢复的闭环：修复接口 → 功能检查通过 → 正式理解验证通过 → 保存关卡完成证据 → 继续下一关。刷新、服务重启和重复请求后，结果与当前位置保持一致。

上位需求为PRODUCT.md、docs/01的L01/L05及docs/05的R2.4。R2.3已交付，验收见[new-system检查报告记录](../new-system/docs/acceptance/R2.3/README.md)。当前课程为HTTP/JSON 1.1.0，包含五个阅读章及三个代码章，原版1.0.0保留。

已有基础：不可变快照、持久检查报告、当前文件摘要比对、课程版本标识、SQLite迁移、带revision的续学接口。缺口：正式理解尝试、服务端完成规则、正式进度读取、首页与工作台真实续学联动。现有续学接口仍固定返回checksAvailable=false，工作台页签尚未接入完整的持久位置保存。

## 本轮范围与规则

以下为沿用需求的实现方案；接口字段、表结构及题目内容在对应任务中确定。

1. 八章继续自由查看。浏览、随堂题和步骤勾选保持原有用途；正式进度由服务端证据计算，预览后续章节不会推进正式位置。
2. 阅读章记录阅读位置，不要求不存在的代码检查，不标为双结果通过。正式代码关卡的先修按课程依赖链计算；阅读节点用于组织学习顺序，不额外增加自报完成门禁。代码关卡之间的前置完成证据必须有效。
3. 三个代码章分别采用已有server-smoke-v1、task-json-v1、notes-json-v1功能策略，搭配各自的正式理解题。启动检查仅表示该章运行任务达标，界面不将其描述为业务接口全部通过。
4. 正式理解题使用改变输入、路径、状态或JSON类型的情境，优先使用可确定判定的预测和选择。与已有随堂题分开，保存题目及规则版本；本轮无需AI参与判分。
5. 理解尝试绑定课程ID、课程版本、关卡、提交、代码摘要和有效功能作业。服务端读取报告确认结果，不接受客户端自报passed。功能结果失败、环境故障、取消、代码已变化或当前文件无法核对时，不能新增正式完成。
6. 完成记录保存双结果引用与规则版本。新代码产生新快照后，已有完成证据仍可查看并明确对应的历史代码；历史证据不能充当新代码检查结果。新尝试失败不删除已获证据，环境故障不降级能力。
7. 理解验证失败可重答，保留尝试历史并提示错误涉及的概念。普通重试不取消已有有效完成。重复或并发请求只生成一次相应完成记录。
8. 旧版1.0.0继续可读、可查报告与恢复位置，正式验证按本版本的题目与规则处理；不能挪用1.1.0题目或通过记录。若旧版缺少正式规则，明确显示该版本暂不支持正式完成，并提供显式进入新版入口，保留旧记录。
9. R2.4记录关卡达标与证据；独立程度仅采用可核实记录。没有帮助使用记录时保持未知，R5再完成画像推导。完成HTTP/JSON后提示数据库/SQL待发布，项目A先修保持原计划。

## 顺序与任务

### R2.4.1 定义正式验证契约

依赖：R2.3。已完成，证据见R2.4验收记录。

- 核对CourseController、课程schema、三种检查策略及依赖图，确定阅读节点与代码节点的进度规则。
- 为三个代码章分别编写正式情境题、判定条件、反馈与规则版本；答案由服务端使用，正式验证的读取响应不包含答案键。
- 明确旧版支持状态、通过证据的有效性和新快照后的展示规则，同步必要的架构、课程及页面规格。

验收：每个代码章都有与目标对应的变式题和明确通过条件；已有随堂题继续只作练习。课程版本与策略不会交叉使用。

接续点：按契约先写“仅功能通过不能完成；两项有效证据才完成”的后端行为测试。

### R2.4.2 持久化理解尝试与完成证据

依赖：R2.4.1。已完成，证据见R2.4验收记录。

- 追加Flyway迁移，保存理解尝试、规则版本、功能结果引用和完成证据。复用现有提交与作业表，不修改历史迁移。
- 实现服务端判定及事务内完成写入，使用唯一约束与幂等键处理重复、并发和同键不同内容冲突。
- 验证课程、关卡、快照、功能策略、作业结果、文件新鲜度及代码先修。读取正式题目、提交答案和读取结果沿用现有本地来源校验与授权边界。

验收：仅功能通过、理解答错、跨版本/跨关卡引用、旧代码报告、无法核对当前文件、环境错误均不新增完成；双结果有效时一次完成；重试可追溯，重启后仍可查询。

接续点：以真实HTTP接口完成一个代码章的正反例，再接进度查询。

### R2.4.3 建立权威进度与续学动作

依赖：R2.4.2。已完成，证据见R2.4验收记录。

- 扩展GET /api/v1/learning/continue，返回服务端计算的关卡状态、停留位置及下一动作，替换固定检查可用值。
- 校验保存位置引用真实课程和关卡，保留expectedRevision冲突保护；完善理解步骤的持久位置。
- 区分正式学习位置与后续预览。双结果达标与下一动作在事务中保持一致；用户点击“下一关”后进入对应章节，最后一关返回项目总结。
- 完成项目时给出HTTP/JSON实际达标结果和后续待发布状态，保留原课程版本。

验收：刷新、直接打开深链接、服务重启能恢复位置；过时请求返回冲突，不能覆盖新位置；浏览下一章不等于完成或解锁；已完成关卡可回看，重复完成不把位置推过多关。

接续点：核对首页、项目目录、工作台三处使用同一份服务端进度。
