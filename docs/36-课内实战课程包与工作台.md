# 课内实战课程包与工作台

「课内实战」位于 `/school`。课程按学期排列，每个实验有独立地址 `/school/:courseId/:labId`。首发为大三上《数据库原理》，课程包来自用户提供的七份上海电力大学实验报告正文。系统采用题目要求、考点提示与合成种子数据，引导学习者逐题实现。原报告的个人资料和既有作答留在本机。

## 数据库原理的工程接续

七个实验共用同一个课程练习库。首次运行载入 `seed.sql`，从 Workbench 和建表实验开始时也可以主动重置为空库，亲手建表、插入数据。后续查询、视图、存储过程和触发器继续使用已有数据库对象；回看前面的实验只切换正在编辑的题目。

每题可保存多条 SQL。运行全部按题目顺序执行已有作答，每题建立独立会话，因此 `SET`、`CALL`、查询输出参数等需要同一会话的语句放在同一题。运行出错前已经完成的数据修改仍按 MySQL 自身的事务和隐式提交规则生效。结果记录对应当时执行的 SQL，草稿修改后可重新执行。题目状态统计成功执行的必做题，供续做参考。

重置可以清空当前课程数据库，或恢复其预置数据。数据库重置保留所有实验的草稿和历史结果。查询表格每个结果集最多展示 100 行；运行器限制查询耗时、进程耗时与输出体积。影响行数来自脚本末条语句。报告导出采用 HTML-based `.doc`，含课程、实验、学生、题目、作答、运行反馈以及结果表，可预览、复制和下载。

数据库原理现有 101 个题组。每个实验末尾新增 5 道选做题，配有考点提示和可观察结果。涉及建表、改成绩或删数据的扩展练习，通过临时表、事务回滚或专用练习对象完成。选做题可保存、运行并随实验报告导出。

课程目录同时显示总题数和必做运行进度。实验页的「原题与实验数据」按原有题号显示材料原文与子问。实验一表 2–7 直接提取自 Word 表格，实验二使用同一数据；实验六平均分格式来自原题图片。实验一、二提供原表 5–7 的 INSERT 脚本，适用于已建表的空库。课程默认种子仍用于扩展练习。报告使用有来源的题目原文。历史作答、结果截图和个人补录记录保留在本机原报告。

## Web Workbench

「对象浏览 (SCHEMAS)」通过 GET `/api/school/courses/:courseId/databases` 列出课程隔离实例中执行账号通过 SHOW DATABASES 可见的库，包含自建库。数据库选择器可以切换或取消选择当前库。GET `/api/school/courses/:courseId/schema?database=库名` 显示所选库对象；运行 SQL、切库和重置后会刷新视图。参见 [MySQL 8.4 INFORMATION_SCHEMA](https://dev.mysql.com/doc/refman/8.4/en/information-schema.html)。

通过 SCHEMAS 的「新建数据库」可创建并选中一个空库。也可单独运行 CREATE DATABASE，或把它写在脚本第一条并接 USE 与其他语句。库名以英文字母开头，可含字母、数字与下划线，最多 64 个字符。执行账号按库授权，MySQL 系统库保留。重置只处理课程预置库，自建库及授权继续保留。

编辑器选中 SQL 时，「运行当前题」与 Ctrl+Enter 优先运行选区。选区结果在当前页面展示，整题运行仍承担保存作答、计入进度与生成报告结果。选区中的合法写入和 DDL 会作用于练习库。使用 SQL Formatter 的 MySQL 语法排版普通脚本，含自定义 DELIMITER 的例程和触发器脚本可以照常执行，排版由学习者控制。参见 [SQL Formatter 用法和限制](https://github.com/sql-formatter-org/sql-formatter#readme)。

结果网格的 Filter Rows 在已返回的行中搜索。CSV 和 Markdown 导出当前筛选后的行，CSV 使用 UTF-8 和带引号的字段。

## 添加课程

在 `new-system/course-packs/school/` 下新增一个以英文小写短横线命名的目录。课程大厅读取各目录的 `course.json`，无需更改导航、前端路由或控制器。

| 文件 | 字段与用途 |
| --- | --- |
| `course.json` | `id` 与目录名一致。填写 `title`、`term`、`termTitle`、`termOrder`、`school`、`major`、`summary`、`engine` 和按顺序排列的 `labs`，其中每项有 `id`、`title`。 |
| `labs/<labId>.json` | 与大纲中的实验 ID 一致。含 `objective`、`requirements` 及 `questions`。每题用固定 `id`、`title`、`requirement`、`hint`、`optional` 与可选的 `starterSql`。 |
| `seed.sql` | `engine: mysql` 时必需。依照课程配置中的 `database` 初始化主库，额外跨库题可声明 `extraDatabases`。 |

`engine: manual` 可承载操作系统、网络实验或软件工程课设的任务要求、作答草稿和报告。接入新的可执行工具链时实现对应的运行方式。已经开始写作答的题目应保留课程、实验和题目 ID，以便继续读取旧草稿。

本地日常实例从运行数据库所属目录的 `school-student.properties` 读取 `name` 和 `number`。有这两个字段时，报告预览自动带入，可在导出弹窗中修改；MySQL 课程可以用 `{studentId}` 生成学号后缀，通用安装使用 `practice` 后缀。此文件在 Git 忽略范围内。

## 接口与隔离

课程接口在 `/api/school/courses` 下，实验资源通过 `/api/school/courses/:courseId/labs/:labId` 读取。其 `run`、`save` 和 `reset` 接受 POST，`export` 接受 GET。草稿版本保存在 SQLite V16 的 `school_lab_drafts` 表。保存和运行会核对旧版本，防止多页面覆盖；服务收到新的草稿时会过滤和 SQL 不再匹配的执行结果。

运行器复用 `MysqlEnvironment` 的镜像、Docker 启动及资源限制，按本机数据目录与课程建立独立容器和卷。课堂脚本经过 `SqlPolicy` 通用输入核验，由限定到课程数据库的 MySQL 账号执行；课外 SQL 课程继续使用原有小语法检查。MySQL 客户端采用非交互二进制模式，允许例程需要的分隔符指令。课程源码目录里的种子属于可信启动配置。参见 [MySQL 8.4 客户端命令](https://dev.mysql.com/doc/refman/8.4/en/mysql-commands.html)。
